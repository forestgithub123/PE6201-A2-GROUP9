报告负责提出论点，代码仓库负责保存可复现证据。报告中的通过率、tokens、turns、cost、案例数量等数字必须来自团队实际运行结果，不能凭印象填写。

1  Why an agent

1.1  Position on the Class 4 Ladder

内部填写说明  先明确本项目位于 rung 7 Agent。再说明 rung 1 至 rung 6 为什么不足。关键不是“Agent 更先进”，而是不同案例需要的步骤数量和顺序会随工具返回结果变化。例如，某案例在发现保单失效或 red flag 后应提前停止，另一个案例则必须继续查多条明细或多个 slot。至少引用两个不同长度的团队案例和各自 turns。

说明是谁决定下一步：模型在运行时依据 observation 决定，而不是开发者预先写死完整路径。

说明为什么 single call、固定 prompt chain 或 routing 不能覆盖动态分支。

说明 parallelisation 只是减少独立调用的 turns，并不能代替 Agent 的动态决策。

简要评价 rung 5 和 rung 6：它们能解决什么，但仍不能完整满足当前任务。

指出 D1 的边界：本作业实现一个 single agent ReAct loop，不是 multi agent。

1.2  Workflow Test and Governance Cliff

  • In the live configuration, the model selects the next action from tool observations, while the ReAct loop executes calls and records results. Developers define the tools and guardrails, not a fixed path for every claim. The scripted backend is used only for reproducibility. Path length varies with the claim: a simple covered claim takes 【】 turns, a multi-line claim requiring pre-authorization takes 【】, and an early escalation stops after 【】. Parallel calls reduce turns only when independent; they do not make the decision. issue_decision_letter is the governance cliff because it affects the member and audit trail. Read-only retrieval remains autonomous, while this irreversible action is protected by a 【suggest / confirm / act】 gate.

The scripted backend replays recorded model moves while executing the real tools, validators and guardrails against the reference fixtures. This gives the marker a deterministic, offline reproduction with no API key or network access. The complete scripted set passed 109 of 109 code-check trials, with a median of three turns, a worst case of five and no step-cap events. With the guard present, the first repeat stopped loudly at turn two with stopped_by=duplicate_action; the step and budget caps would only have bounded the damage later without naming its cause.

5.2  Tool Interface or Prompt Failure

For the second ablation, we removed the service-date validity constraint from get_preauthorisation. On CLM-8894, the damaged interface returned PA-5640 even though it expired on 31 May and the service occurred on 9 September. The same agent path therefore approved line 29881 instead of requesting a current authorisation. Restoring the date-bound contract restored the correct request_document result.

Observed failure

Correct layer for the fix

Tool interface: date validity is deterministic source-boundary logic that every caller should receive consistently.

Why the other layers are wrong

A prompt would duplicate date comparison in a stochastic model; loop guards cannot judge whether a finite, syntactically valid lookup returned an expired record.

Before and after

Working: 5 turns, 42,000 + 840 estimated tokens, 1/1 pass. Minus X: 5 turns, 32,400 + 720, 0/1. Restored: 1/1. Whole set: 109/109 -> 103/109 -> 109/109; actual API cost US$0.

The full scripted battery confirmed the interface diagnosis: deleting the date contract reduced the pass rate from 109/109 to 103/109, failing all three trials for each of the two expired-preauthorisation cases, CLM-8894 and CLM-9304. Restoration returned the set to 109/109. The broken version was superficially cheaper because it accepted false evidence sooner, which is why cost cannot substitute for correctness. Both reproductions are deterministic and free; their token and model-equivalent cost figures are scripted estimates, not measured API spend.
